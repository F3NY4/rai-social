# Развёртывание

## GitHub Pages

1. Загрузите исходный проект в репозиторий GitHub. Исключения `.gitignore` закрывают каталог сборки, браузерные отчёты и файлы GGUF.
2. В Settings → Pages выберите GitHub Actions в качестве источника.
3. В Actions запустите **Deploy to GitHub Pages**. Файл `.github/workflows/deploy.yml` берёт базовый путь из `configure-pages`, проверяет типы и модульные тесты, собирает и публикует `build/`.
4. Откройте URL из результата workflow в Safari. Прямые ссылки на разделы используют фрагменты, например `/#messages` под соответствующим базовым путём.

## Другой статический хостинг

```sh
npm ci
npm run build
```

Загрузите содержимое `build/` на бесплатный статический HTTPS-хостинг. Например, Cloudflare Pages может собирать проект командой `npm run build` и публиковать каталог `build`. Если сайт находится в подкаталоге, соберите его с `BASE_PATH=/имя-каталога`. Отдавайте `.wasm` с MIME `application/wasm`, а JavaScript и service worker с обычным JavaScript MIME. Входная страница и область видимости Service Worker должны находиться в одном префиксе. Однопоточный WASM не требует заголовков COOP и COEP.

Для локальной проверки `npm run preview` использует localhost. iPhone, подключённый к локальной сети по обычному HTTP, не получает secure context, необходимый для PWA, OPFS и части криптографических API. Для телефона используйте опубликованный HTTPS-адрес.
